## 比较方式

采用共享首候选的配对流程：

- `single`：首轮候选的最终流程状态、实际独立验收、一次模型调用尝试及相应耗时。
- `feedback`：包含同一首轮的完整 `repair` 结果，最多 3 次模型调用尝试。

首轮只实际生成和验收一次，后续反馈从相同原始提交与源码上下文继续。两列不是独立采样；本次实际调用数等于 `feedback.modelRequests`，不能再加上共享的 `single` 调用数。

两种流程的预算不同，结果可以描述增加调用预算后的变化。这批旧实验没有“同预算、无反馈重采样”对照，不能将变化单独归因于失败反馈。

## 运行

```powershell
cd D:\项目\RepoPilot
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\项目\RepoPilot\Start-RepoPilot.ps1 bench D:\项目\RepoPilot\benchmarks\smoke.json
```

提示后复制对应百炼业务空间的完整 API Key，回到终端只按回车。程序按任务顺序运行，每轮显示任务编号、候选路径和 SHA-256；打开审阅后输入 `yes` 才会独立验收。默认两项任务最多 6 次模型调用尝试，成功或停止条件触发后提前结束。

未确认审阅、任务错误或缺陷未复现时停止后续任务，保留所有预定任务行。剩余行标记 `not_run`。重新运行会创建新评测，不恢复旧会话或复用历史成功报告。

## 时间与结果

从本步开始，`repair.json` 新增单调时钟计时：

- `wallMs`：该流程的总耗时。
- `reviewWaitMs`：审阅回调耗时，包含终端确认等待。
- `activeMs`：`wallMs - reviewWaitMs`，包含基准、模型、工具、文件操作和独立验收。
- 每轮记录自身耗时、累计耗时、调用次数和最终状态；首轮即使错误或拒绝审阅也有记录。

单次列使用首轮结束时的累计耗时，反馈列使用完整流程耗时。评测外层读取任务集和写汇总的开销不计入策略耗时。旧报告不会补造计时或自动混入新评测。

耗时是本次本机运行记录，受主机负载和模型服务延迟影响；当前未进行多次采样或专门的性能控制实验。

每列分别统计 `resolved`、`unresolved`、`error`、`not_reproduced`、`awaiting_review` 和 `not_run`。任务分母始终是固定任务集的全部任务；未运行、未审阅或环境错误不冒充已修复或模型修复失败。

| 评测状态 | 含义 | CLI 退出码 |
|---|---|---|
| `completed` | 全部任务完成有效验收，结果可以包含 `unresolved`。 | 0 |
| `incomplete` | 某任务等待审阅、错误或未复现，已停止并保留其余行。 | 1 |
| `error` | 任务集、固定输入或评测程序故障，本次比较不可用。 | 2 |

`completed` 表示评测运行结束，不代表所有任务修复成功。

## 本机实测

2026-11-10，使用 `dashscope/qwen3.7-plus` 完成 `smoke-v1` 的两项任务。两列共享首轮，整次评测实际发起 3 次模型调用。表中执行耗时已扣除审阅等待。

| 任务 | 单次候选 | 有限反馈 | 单次 / 反馈执行耗时 |
|---|---|---|---:|
| 分页空数组 | `resolved`，1 次 | `resolved`，1 次 | 27.0 / 27.0 秒 |
| Unicode 连字符 | `unresolved`，1 次 | `resolved`，2 次 | 24.1 / 67.7 秒 |
| 合计 | 1/2 项通过，2 次 | 2/2 项通过，3 次 | 51.1 / 94.7 秒 |

Unicode 首轮删除连字符转义，目标通过但字符类回归失败。第二轮收到失败反馈后改用 Unicode 转义，目标与 6 项回归全部通过。两项交付补丁均通过独立验收和回放检查。

- 本机对照表（`bench-uq4k9n/benchmark.md`）及机器可读报告（`bench-uq4k9n/benchmark.json`）。
- 分页验收（`baseline-sPgmC8/report.json`）、Unicode 首轮验收（`baseline-MXeWZ3/report.json`）、Unicode 第二轮验收（`baseline-pQZWaX/report.json`）。
