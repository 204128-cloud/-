# 同预算的反馈与无反馈对照

`bench-equal <suite.json>` 在同一固定任务上分别运行两条独立策略：

| 策略 | 输入 | 每任务调用上限 |
|---|---|---:|
| `no_feedback` | 每次只使用原始问题、基准测试摘要与授权源码，提示词保持相同 | 3 |
| `feedback` | 首轮使用相同原始输入；符合重试条件时追加上一候选和实际失败测试摘要 | 3 |

两臂独立生成和独立验收，不共享首候选。任务按清单顺序执行，策略先后按任务序号交替：第一项先无反馈，第二项先反馈，第三项再先无反馈。两策略使用相同模型配置、固定提交、源码选择与原始上下文指纹，每次请求前后及审阅前后检查固定输入。源码或基准上下文不一致使比较无效。

“同预算”指相同的三次上限。成功、重复候选或安全停止规则可能提前结束，两臂不保证消耗同样多的调用。两臂沿用同一修复器、人工审阅和独立验收；无反馈分支也不绕过错误、未复现或完整性检查。

## 计数与结果

- 每任务最多 6 次请求尝试，新增三项 `extended-v1` 最多 18 次。
- `summary.actualModelRequests` 为真正进入请求回调的总尝试数，包含失败尝试；它不是 HTTP 用量或计费记录。
- `summary.noFeedback.modelRequests` 与 `summary.feedback.modelRequests` 分别记录各臂尝试。正常完整运行时，两者相加等于总尝试数。
- 原来的 `bench` 仍是共享首轮的 1 次 / 最多 3 次比较，实际尝试只计反馈完整流程。两种报告的计数方法不可混用。
- 拒绝审阅、未复现、基础设施错误或中断会停止后续策略和任务；未运行项仍在固定任务分母中，分别列为 `not_run`。
- `completed` 只表示所有策略完成有效验收，可以包含 `unresolved`；输入变化为 `error`，本次比较无效。

时间记录沿用 `wallMs`、`reviewWaitMs` 与 `activeMs`，执行时间扣除审阅回调等待。独立采样、服务波动、不同的实际调用数和小样本都会影响结果；一次对照不能证明反馈的统计因果收益，也不能推算总体模型修复率。

## 真实运行入口

准备新增构造任务无需密钥：

```powershell
cd D:\项目\RepoPilot
node scripts/prepare-extended-cases.mjs
```

下列命令会调用真实模型，最多 18 次，可能产生 API 费用。离线实现验证不执行该命令；已完成的本机真实运行见下方“本机实测”：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\项目\RepoPilot\Start-RepoPilot.ps1 bench-equal D:\项目\RepoPilot\.repopilot\extended-v1\suite.json
```

密钥提示出现后，复制完整百炼北京按量 API Key，回到终端只按回车。每轮显示任务、策略、轮次、候选路径与 SHA-256；打开并审阅对应补丁后输入 `yes` 才会独立验收，其他输入保留候选并停止。Ctrl+C 可中断。当前实现不恢复中断的评测；重新执行会开启新的运行并重新计数。

## 报告

每次生成独立的 `.repopilot/runs/bench-*/benchmark.json` 与 `benchmark.md`，设计标记为 `equal_budget_independent`。报告记录环境、固定输入与上下文哈希、实际顺序、各策略结果、调用尝试、耗时与独立的修复/验收报告引用，不保存提示词、源码、原始服务响应或密钥。

聊天内 `/runs` 可找到新评测，`/report <运行ID>` 显示两臂总尝试数及关联修复运行 ID。逐项对照表在 Markdown 报告中，完整字段在 JSON 中。

## 离线验证

自动化验证使用私有故障仓库和注入的模拟候选，真实运行基准、原测试、Git worktree、补丁审阅指纹核对与独立回放，未调用真实模型，也没有修复或修改冻结的三个构造案例。这些测试结果不是百炼的修复表现。

本轮完整回归 320 项全部通过，类型检查、构建和编译版比较器验证通过。双任务集成测试中记录的 7 次调用为模拟回调（无反馈 4 次、反馈 3 次），用于校验计数，不能写作真实模型成绩。
